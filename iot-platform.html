Industrial IoT Sensor Analytics Platform

From raw sensor readings to a 24-hour failure warning and a maintenance plan.

  • 166 of 171 failures caught (rule baseline: 43)
  • 876,100 sensor rows
  • 459 tests
View on GitHub

Problem

A maintenance team does not need an anomaly score. It needs to know which machine to look at tomorrow, which component is likely at fault, and whether acting is cheaper than waiting. This platform runs that whole chain end to end with one command.

Data

Source
Synthetic Microsoft Azure Predictive Maintenance dataset.
Scale
100 machines, hourly readings across 2015 — 876,100 sensor rows.
Events
3,919 errors, 3,286 replacements, 761 failures.
Injected issues
Stuck sensors, gaps, spikes and duplicates, added deliberately to test the cleaning layer.

Approach

  • 45 contract checks run before anything is trusted.
  • Bronze — SHA-256 skip of unchanged files.
  • Silver — type casting, de-duplication, spike removal, stuck-sensor detection, gap fill up to 3 h, quality flags.
  • Gold — 3-hourly features, 24 h-ahead labels, monthly MTBF, MTTR, availability and cost.
  • A star schema with 5 dimensions, 6 facts and 5 views; 11 pipeline steps in about five minutes.
  • Three models: HistGradientBoosting for failure within 24 h, multi-output gradient boosting for which component, Isolation Forest for anomaly.
  • Time-based split, tested on Oct–Dec 2015 only. Each model must beat a baseline before it is registered in MLflow.

Limitations
& honest notes

  • The data is synthetic, with strong and consistent patterns. Results on a real plant would be lower — this number is not a forecast of field performance.
  • Validation is on a single time-based split, Oct–Dec 2015.
