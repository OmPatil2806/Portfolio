Automotive Diagnostic Log Analyzer

Flags a developing fault in OBD-II logs before the fault code appears.

  • 90% faulty trips detected
  • 7.5% false alarms
  • F1 0.87 on unseen trips
View on GitHub

Problem

A diagnostic trouble code appears once a fault is already established. The useful window is earlier, while a subsystem is drifting out of its normal range but has not yet tripped a code. This tool learns what normal looks like from real logs and watches for that drift.

Data

Normal behaviour is learned from real Vehicle Energy Dataset logs. Six faults were then injected so the system could be evaluated against a known ground truth on trips it had never seen.

Evaluation set
240 unseen trips — 120 normal, 120 faulty.
Injected faults
Six types, from vacuum leak to hybrid battery wear.
Model type
Machine learning only — no LLM anywhere in the system.

Approach

  • Isolation Forest over trip-level features, combined with a range score computed per subsystem.
  • Root-cause attribution maps the anomalous signals back to the subsystem most likely responsible.
  • A vehicle health score summarises a trip into one number a non-specialist can read.
  • Reports export to PDF, HTML and JSON; a Streamlit dashboard and a CLI pipeline share the same engine.
  • A trained model and sample trips ship with the repository so it runs without setup.

Limitations
& honest notes

  • Faults were injected rather than observed in the wild, so detection rates reflect the injected signal strength.
  • Early warning varies sharply by fault: a dirty MAF sensor is flagged before its code 60% of the time, an engine misfire only 20%.
  • Dirty MAF sensor root-cause accuracy is the weakest at 65%, despite being detected on every trip.
